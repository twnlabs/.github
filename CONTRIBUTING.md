# Contributing to TWN Labs

Thank you for taking the time to contribute. We welcome issues, ideas, and pull requests.

## Quick start (TL;DR)
1. Create a branch from `main` using a descriptive name, e.g. `feature/short-title` or `fix/issue-123`.
2. Make your changes; follow the repo's lint/format rules and run checks.
3. Commit using conventional commits (e.g., `feat:`, `fix:`, `docs:`, `chore:`).
4. Open a PR to `main` and fill in the template with context, screenshots, and test notes.
5. Request a review from the maintainers and address feedback.

## Branching & commits
- Prefer small, focused PRs.
- Use present tense and imperative mood in commit subject lines.
- Reference issues when applicable: `fix: handle edge case (closes #123)`.

## Code quality
- Match the project style (linters, formatters, type checks).
- Add or update tests when behavior changes.
- Do not commit secrets or credentials; use environment variables.

## Pull Request checklist
- [ ] Scope is clear and changes are atomic
- [ ] Lint/format/test pass locally
- [ ] Docs/README updated if user‑visible behavior changed
- [ ] Screenshots or logs included if UI/CLI output changed
- [ ] Linked to related issues or discussion

## Security
Please report security vulnerabilities privately at https://twnlabs.com/security. Do not open public issues for security reports.
